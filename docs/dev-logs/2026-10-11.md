  - 结束帧 `{"is_speaking": false}` 后等 2 秒收尾定稿再断开；断连发 Error + Ended（只发一次）

- **联调文档** `ClassAssistant-FunASR-联调文档.md`（给 Redmi 机器上的 mimo v2.6 pro）
- 版本号同步 `1.1.0`（对应分支 v1.1.0.0）
- 对照对接文档跑了一轮**对抗式复核**（协议/事件语义/Rust 并发/前端配置四个视角 + 逐条反驳），确认 6 条问题并全部修复：
  1. `start_ms` 记账时机（应在新句首条草稿时记，而非句尾）——转写时间戳更准
  2. 空的 `2pass-offline` 未清草稿 → 会串进下一句草稿
  3. 发送无超时会挂住下课流程 → 加 5 秒超时；发送失败/服务端提前关闭时补发错误事件（原先生硬结束，界面无提示）
  4. 推流失败直接退出会吞掉已排队的错误事件 → 改为继续送完事件
  5. 切到 MiMo 时模型名可能为空导致请求失败 → 前后端都补默认模型名
  6. 后端未校验总结密钥、提示文案未区分识别/总结 → 已补齐

- **修复「末句定稿丢失」高危问题**（对抗式复核回报，`session/manager.rs`）
  - 原问题：「下课」时 `handle_end` 不等 ASR 收尾就快照转写并发起总结，FunASR 结束帧后 2 秒收尾窗口内的末句 `2pass-offline` 进不了总结、不计字数统计，且 flush 已过、尾段滞留 pending 不落盘——末句三丢
  - 修法：`ManagerCmd::AsrDone` 信号（run_pipeline 所有退出路径末尾发出，FIFO 保证尾段先入队）；`handle_end` 只停采集记时间戳，定稿（统计→flush→写 meta→发起总结）延到 `AsrDone` 后的 `finalize_session`（幂等）；8 秒兜底定时器防 worker 挂死
  - 回归测试：自定义 ASR mock 在 `finish()` 后才吐末段，断言末段计入 meta 统计、进总结请求、落盘 transcript.md
  - 45 个单元测试全绿（`cargo test --release`）+ `npm run build` 干净
- **v1.1.0.0 测试包**：`npm run tauri build` → `output/ClassAssistant-v1.1.0.0-test/`（绿色版 ClassAssistant.exe + WebView2Loader.dll、安装版 ClassAssistant_1.1.0_x64-setup.exe）+ `ClassAssistant-v1.1.0.0-test.zip`，交涵涵去 Redmi 联调
