- **修复「末句定稿丢失」高危问题**（对抗式复核回报，`session/manager.rs`）
  - 原问题：「下课」时 `handle_end` 不等 ASR 收尾就快照转写并发起总结，FunASR 结束帧后 2 秒收尾窗口内的末句 `2pass-offline` 进不了总结、不计字数统计，且 flush 已过、尾段滞留 pending 不落盘——末句三丢
  - 修法：`ManagerCmd::AsrDone` 信号（run_pipeline 所有退出路径末尾发出，FIFO 保证尾段先入队）；`handle_end` 只停采集记时间戳，定稿（统计→flush→写 meta→发起总结）延到 `AsrDone` 后的 `finalize_session`（幂等）；8 秒兜底定时器防 worker 挂死
  - 回归测试：自定义 ASR mock 在 `finish()` 后才吐末段，断言末段计入 meta 统计、进总结请求、落盘 transcript.md

### 下午：联调回执处理（回执 #2 + 新功能）

- **修复 FunASR 握手子协议回显依赖**（联调回执 #2：「无法连接 FunASR 服务」）
  - 根因：**tungstenite 0.26 握手内部校验**——客户端声明了 `Sec-WebSocket-Protocol: binary` 就强制要求服务端回显，否则报 `NoSubProtocol` 拒连；而 FunASR（WebSocket++ 0.8.2）的 101 响应从不回显子协议（RFC 6455 §4.1 允许省略）
  - 修法（`asr/funasr.rs`）：`build_request(url, with_subprotocol)` 可选声明子协议；新增 `connect_ws()` **先不声明子协议**连接，若报 `SecWebSocketSubProtocolError`（部署侧回显代理场景）则自动带 `binary` 重连一次；`probe`/`start` 都走它
  - 回归测试：本地 `TcpListener` 假 WebSocket 服务端，不回显 / 回显 binary 两种握手都连通（测试写 key 提取时踩坑：不能整行 to_lowercase，会破坏 base64 key 大小写导致 accept 不匹配）
- **新增「留存最近一次总结」**（防复位误触丢总结）
  - 后端：`SessionStore` 加 `write_last_summary`/`read_last_summary`（存 `last_summary.md`），总结成功时写入；新 IPC `get_last_summary`
  - 前端：UiState 加 `lastSummary`（新总结生成即更新，**RESET 不清**）；启动时加载；SummaryPane 空闲且无本节总结时显示「最近一次」留存（复制按钮照常可用；录音/总结中不显示避免混淆）
