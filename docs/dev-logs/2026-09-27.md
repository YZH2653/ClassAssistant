## 二、遇到的问题

- 涵涵双击 `target/debug/class-assistant.exe` 后窗口显示「无法访问 / localhost 拒绝连接」→ debug 版 exe 会去连 Vite 开发服务器（localhost:1420），必须用 `npm run tauri dev` 启动。已新增 `启动开发.bat` 并在 CLAUDE.md 写明
- 执行 `cargo test` 时被杀毒软件拦截打断，重新执行后正常通过
- **MinGW 工具链坑**：新增 tokio/async-trait 依赖后，**debug 测试二进制无法启动**（0xc0000139 STATUS_ENTRYPOINT_NOT_FOUND，无任何输出）。排查确认：主程序 exe 正常、旧测试二进制正常、导入表全部合法，属 MinGW ld 对大型 debug 测试二进制的链接产物异常（与此前 `export ordinal too large` 同源）。**解决：测试用 `cargo test --release`**（strip + LTO 链接正常），已写入 CLAUDE.md
- `src-tauri/Cargo.toml` 只有换行符（CRLF/LF）差异，随本步一并提交
- 自测发现 `meta.json` 统计字段（segment_count/word_count）未写入 → 已修复并加回归断言
- Windows 计时器粒度约 15.6ms，`sleep(1ms)` 实际约 13ms，导致按名义步进估计的测试等待时间不足 → 测试改为轮询等待段落产生
- MiMo ASR 接口是「一次提交一段音频 + 流式返回文字」，不是逐帧双向流 → 实时转写按 8 秒分片，文字延迟约等于片长；接口约束：仅 wav/mp3、Base64 ≤ 10MB
- `effective_base_url` 首版把预填的默认地址当成「用户手动填写」，导致密钥前缀识别失效（单测发现）→ 改为非默认地址才算手动指定
